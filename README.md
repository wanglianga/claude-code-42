# 城市宠物公园入园预约与冲突处置平台

## 原始需求

> 建设城市宠物公园入园预约与冲突处置平台，可使用 Vue 3、FastAPI 和 PostgreSQL。宠物主人预约入园时提交宠物品种、体重、疫苗、绝育、攻击史、牵引要求和入园时段。平台根据大型犬区、小型犬区、社交区、训练区和活动区容量生成预约结果。入园时，工作人员核验疫苗、犬证、牵引绳和主人身份；未通过核验的宠物不能进入自由活动区。园区内，巡场员记录宠物追逐、吠叫、争抢玩具、咬伤、主人未清理粪便和设备损坏。若发生宠物冲突、人员受伤、疫苗过期、主人拒不配合或活动区超员，平台要把巡场员、园区管理、宠物主人、合作医院和客服串到同一事件。事件关闭后，伤情、赔付、黑名单、活动资格和园区设施整改进入宠物档案和园区运营记录。园区还要按宠物体型、品种和活动类型复盘冲突，判断是否需要重划分区、增加巡场员或限制某些宠物活动。黑名单变化会影响后续活动报名。平台还要把宠物行为、主人责任、园区设施和医疗处置放在同一事件中，园区后续限制入园、调整分区或处理赔付时都有证据可查。

## 技术栈

- **前端**：Vue 3 + Vite + Element Plus + Pinia + Vue Router + ECharts（nginx 非 root 镜像托管）
- **后端**：FastAPI + SQLAlchemy + PostgreSQL（JWT 认证 + 角色权限控制）
- **部署**：Docker Compose 一键启动（app 多阶段构建、非 root 运行、HEALTHCHECK）

## 一键启动

```bash
cp .env.example .env        # 可选，不改则用默认配置
docker compose up -d --build
```

- 前端访问地址：`http://localhost:${CC_PUBLISH_PORT}`（`.env` 中的 `CC_PUBLISH_PORT`，默认 3042）
- 实际映射端口可用 `docker compose port frontend 8080` 查询
- 仅前端服务发布到宿主端口；PostgreSQL 与后端仅在 compose 内部网络互访（前端 nginx 将 `/api` 反代到 backend）
- 首次启动后端自动建表并写入演示数据（账号、分区、宠物、今日预约、历史巡场记录与一桩已关闭的示例事件）

停止并释放资源：

```bash
docker compose down            # 保留数据卷
docker compose down -v         # 连同数据一起清空
```

## 演示数据

- **分区**：大型犬区(20)、小型犬区(30)、社交区(25，禁攻击史)、训练区(15)、活动区(40，预约该区即活动报名)，容量均按时段计算
- **时段**：上午 09:00-12:00 / 下午 13:00-17:00 / 晚间 18:00-21:00
- **今日预约**：豆豆→小型犬区、大黄→大型犬区、球球→社交区（疫苗过期，核验将不通过）、黑豹→训练区
- **历史事件**：`E-SEED-0001` 黑豹咬伤豆豆事件（已关闭），含双方冲突档案（入园状态/牵引/主人陈述）、责任认定 80:20、医疗费 800 元按比例结算赔付 640 元、黑豹警告级黑名单、禁止进入社交区+需戴嘴套、社交区隔离网整改完成

## 关键业务流（建议演示路径）

1. **预约**：`owner1` 登录 → 预约入园 → 选宠物/日期/时段，分区卡片实时显示剩余容量 → 提交生成预约结果（确认/候补/拒绝均带原因）。预约单绑定犬只免疫状态、牵引规则与主人联系方式，冲突发生后可快速定位双方。`owner2` 用球球（疫苗过期）预约会被拒绝；黑名单宠物预约/活动报名同样被拒绝。
2. **入园核验**：`gate1` 登录 → 入园核验 → 对今日预约逐项核验；球球的疫苗项不通过 → 提交后禁止入园，并可一键升级为「疫苗过期」事件。
3. **巡场上报**：`patrol1` 登录 → 上报咬伤/追逐等记录（双方冲突可选择对方宠物并填写冲突位置）→ 「升级事件」，平台自动把巡场员、园区管理、宠物主人、合作医院、客服串到同一事件。
4. **冲突责任判断**：冲突事件详情页「冲突责任认定」标签——双方档案卡展示入园核验状态、牵引、疫苗、攻击史与主人联系方式；双方主人可各自提交陈述；巡场员上传现场照片；`manager1` 查看规则建议（未拴绳/攻击史/疫苗未过/违反限制自动加分）后认定双方责任比例与处置级别（警告/限制入园/永久拉黑，直接影响双方后续预约权限）；医疗费用按责任比例生成结算单与赔付记录。
5. **五方协同**：事件详情页中——医院登记伤情与费用、客服登记并核销赔付、园区管理加黑名单/活动资格限制/设施整改，各方均可在时间线发布进展。
6. **关闭归档**：`manager1` 关闭事件并填写处置结论 → 伤情、赔付、黑名单、活动资格、设施整改、责任认定与结算明细归档进宠物档案与园区运营记录；关闭后整改状态、责任认定、陈述等一律只读。
7. **复盘分析**：`manager1` → 复盘分析，按体型/品种/分区/行为类型查看冲突图表，发布「重划分区/增加巡场员/限制特定宠物活动」决策；分区管理可直接调整容量与准入规则。

## 验证方式

本项目以「宿主 docker compose up 健康 + 关键业务流可走通」为验证通过标准：

```bash
docker compose up -d --build
docker compose ps                                   # 三个服务均 healthy/running
docker compose port frontend 8080                   # 取实际映射端口
curl http://host.docker.internal:$(docker compose port frontend 8080 | cut -d: -f2)/   # 前端页面
curl -X POST http://host.docker.internal:<端口>/api/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"username":"owner1","password":"owner123"}'  # 返回 JWT 即后端正常
```

浏览器打开前端地址，按上方「关键业务流」逐角色登录演示即可。

    └── src/views/            # 登录/仪表盘/宠物/预约/核验/巡场/事件协同/黑名单/复盘/分区/运营记录
